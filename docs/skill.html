Skill 文档：方法与纪律。

这份文档是报告的生成规范，不是使用说明。它规定流程顺序、判定阈值、必须披露的字段和交付前的自检项。 任何一轮报告都必须能对着这份文档逐条核对。

一、铁律 二、七步流程 三、逐场判定规则 四、购买方案层 五、数据源 六、报告骨架 七、串关的结构性事实 八、核心 API 九、交付前自检 参考文件

产出一份可复算的报告：把赔率还原成概率，用盘口之外的独立信息做出自己的概率，再把两者与公众资金流三方对照，并对每一场写出综合预测与购买方案。

一、铁律

  1. 每一场必须有综合预测。在售 N 场就写 N 行，顺序固定为 比分（top-5 分布）→ 总进球（区间 + 大/小）→ 胜平负。不允许只写焦点场。
  2. 每一场必须有购买方案。落到具体玩法与选项（主胜/平/客胜/让球一侧/总进球某桶/回避），并给出仓位与否决条件。理由里至少含一个数字。
  3. 比分永不给单值。两轮回测 top1 命中 0/23，top3 42.9%，top5 71.4%。只给带概率的排名分布和累计覆盖率。
  4. 模型必须有盘口之外的输入。只用盘口反解 λ 再回推概率，是复述盘口而不是预测（偏差恒 <3pp）。必须接入捷报的主客分离得失球。
  5. 报告只做定价与情报分析，不承诺收益。概率是模型与盘口的推算值。
  6. 所有数字必须来自脚本输出，不得手写估算。
  7. 每个进入模型的数字都要能追到源；不能追源的进文字并标「待验证」。
  8. 回测先于结论。每轮必须把上一轮已完赛场次跑一遍 backtest()，把「实际命中率 vs 盘口隐含概率」写进报告，再据此调整阈值。
  9. 本 Skill 只沉淀方法与版式，不保存任何一轮的具体赔率、场次或结论。

二、七步流程

按顺序执行，不要跳步。

#步骤要点
1回测上一轮拿到已完赛比分，用 backtest(preds, results) 跑逐市场命中率，与待验证清单核对。这一步在采集新数据之前做。
2采集竞彩官网在售场次（全部玩法 + 支持率 + 官方概率）、捷报逐场（主客分离得失球、盘路、18 家初盘与即时盘、天气）、直播吧与搜索补齐伤停/动机。
3建模predictMatch(row) 一次产出 λ（市场 + 独立 + 伤停修正）、比分分布、总进球桶与区间、胜平负、让球、双方进球、半全场。
4判定与方案verdict 给简明判定，rec 给完整购买方案。不要手改阈值。
5补齐逻辑按分析框架八节检查表逐项过，标出进模型 / 进文字 / 因缺数据降级。
6组装按两篇式结构写 HTML：第一篇只摆事实，第二篇只给结论。
7渲染与交付A4、printBackground、margin 0；PDF 落到工作区，交付链接 + 3 个核心结论。

三、逐场判定规则

先算四个量：

dev[i]  去水概率
Δ[i]    = 支持率 − 去水概率        （pp）
md[i]   = 模型概率 − 去水概率      （pp）
ev[i]   = p × odds − 1
条件级别理由模板
SPF 未开售，仅让球盘，模型最高侧 EV > 2%关注模型 61.2% vs 隐含 47.0%，EV +12.8%
支持率第一方向 ≠ 去水第一方向关注资金在平局（Δ+5pp）与定价相反，回测中此类场次定价方 3/3 命中，采信定价
Δ ≥ +15pp 且模型不支持该侧回避人气 +20pp，模型仅 15.3% 低于去水 22.0%，价格不含补偿
Δ ≤ −8pp 且 模型同向 且 max|md| ≥ 2pp关注缺口 −8pp 且模型同向（33.2% vs 28.3%），EV +5.1%
max|md| ≤ 3pp观望模型与去水偏差 1.5pp，定价有效
其余中性模型偏差 3.1pp，人气 Δ 5pp，无结构性错价
为什么删除「冷端价值小注」：第一轮回测中，冷端选项（Δ ≤ −8pp）实际兑现 30.0%、盘口隐含 26.3%，只高 3.7pp； 热端兑现 59.1% 对隐含 49.2%。30 样本的标准误约 8pp，两者都落在噪声内。Δ 不是定价信号，只是风险提示。

四、购买方案层

每场必须给出完整方案，不允许只写「关注/观望」就结束。

级别含义仓位
主推有跨轮回测支撑的结构性信号，模型与市场同向计划资金 1–2%
小注单一市场有正 EV（让球盘 EV>2%、大小球模型与盘路同向）0.5–1%
观察无边际或信号冲突；必须写明「等什么」（首发 / 临场价格）0
回避人气过热（Δ ≥ +15pp）且模型不支持0，并注明为什么

超短赔主推规则

去水第一方向概率 ≥ 66% 且 模型同向 且 该侧伤停修正 ≥ −0.15 且 资金方向无分歧 → 主推单关。任何一条不满足即降级为观察，理由写明。

方案概率采用跨轮回测经验值 91.7%（11/12，12 样本，标准误约 8pp），不是模型输出，报告中必须加星号注明。

焦点场加详

人气 Δ ≥ 15pp、伤停修正 ≥ 0.2、价格移动 ≥ 0.15 三者居其一即为焦点场，方案必须包含：主选与备选玩法、比分娱乐仓建议（≤0.5%/注，取比分分布 top2）、「什么情况下放弃」的临场否决条件。

周三004 费内巴切 vs 利物浦｜主推｜焦点
  主选：胜平负（单关）客胜 @1.33｜去水 66.0% / 隐含 75.2%｜仓位 1–2%
  理由：超短赔区跨轮回测 11/12=91.7%；模型同向；费内巴切换帅 + 5 人伤
  否决条件：临场首发显示萨拉赫/范戴克全部轮休 → 放弃
  比分娱乐仓：1-2（9.7%）、1-1（9.3%）各 0.5%

C直播吧 zhibo8.com伤停、首发、赛程冲突、动机线索定性，需第二来源确认
D联网搜索xG/xGA、官方公告、裁判、联赛形势、换帅与预计首发每个数字必须能点回原页

扩展源（按缺口启用）：球探 zq.titan007.com（盘路与标准盘对照）、捷报资料库、500 彩票网、OddsPortal / Oddspedia（跨庄变价方向）、Betfair / Smarkets（真实成交）、FBref / Understat（xG）、Sofascore / FotMob（首发）、Transfermarkt（伤停与身价）、中国天气网。

B 层是命脉。没有主客分离得失球，独立模型无法建立，报告退回「盘口复述」状态——此时必须在数据卫生层写明 「独立模型缺失，本报告仅为盘口分析」。

解析陷阱

  • 捷报指数页表格用大写 <TR> <TD>，正则必须加 re.I。
  • 部分公司（如立博）不开亚盘，只有 12 个数据列。不要删除空单元格来对齐列，否则整体错位，会算出「主胜 1.06」这类荒谬值。
  • 解析后做合理性校验：三项欧赔均 ≥ 1.01 且倒数和落在 1.00–1.30，不通过就不计入均值。

六、报告骨架

两篇式：第一篇只摆事实，第二篇只给结论。读者只看第二篇能做决策，只看第一篇能核查依据。

篇章节内容
一1 回测校准上一轮逐市场命中率 + 盘口隐含对照 + 待验证清单状态
2 定价引擎margin、去水、λ 三来源、比分矩阵、总进球逐桶 EV
3 基本面官方伤停表、历史交锋、盘路（主客分开）、天气场地
4 市场情报初盘→即时、竞彩 vs 国际偏离、人气税热冷两端
5 数据卫生八条检查项、源清单（含访问时间）、缺失字段、伤停修正披露
二6 逐场综合预测每场：①胜平负 ②总进球（方向 + 8 桶）③比分 top-5 分布
7 逐场购买方案级别 + 玩法 + 选项 + 赔率 + 概率/隐含 + EV + 仓位 + 否决条件
8 全量总表赔率/去水/支持率/λ/综合预测/级别/方案
9 执行层串关测算（全部标 EV，结论固定单关优先）、资金管理、复核时点
10 风险披露免责、样本量、开赛前 60 分钟重跑提示

七、串关的结构性事实

每腿 p × odds 恒等于 1/(1+margin)。margin 13.9% 时：

串关返还率说明
单关0.878基准
两串0.7710.878²
三串0.6770.878³
五串0.5240.878⁵
串关 EV 必然为负，倍率越高越负。这不是选腿的问题，是结构问题。报告必须列出至少三组实测串关并给出 EV，结论固定为「单关优先」。

八、核心 API

函数作用
devig(odds)去水，返回 {p, m, overround}
grid(lambdaTotal, w, rho)12×12 泊松 + Dixon-Coles 比分网格
summarize(g) / topScores(g,n)汇总胜平负/大小球/双方进球；最高概率比分
goalBuckets(g) / goalIntervals(g)总进球 8 桶与 4 区间
rqProb(g, hc)让球盘三项概率（hc 为主队视角让球数）
hafu(g)半全场 9 项分布
fitFromZJQ(zjq, spf) / fit2D(spf)市场映像：由盘口反解 λ 与 w
teamStrength(home, away, form)独立强度模型：比率法 + 样本量收缩（K=8）+ 近 6 场状态（权重 0.15）
blendModels(market, team, k)融合，默认 k = 0.35
predictMatch(row)一次产出全部：λ 三来源、比分分布、总进球桶与区间、胜平负、让球、双方进球、半全场、判定、购买方案
buildRecommendation(...)购买方案层：级别 + 玩法 + 仓位 + 否决条件
backtest(preds, results)回测校准：逐市场命中率与盘口隐含对比
ev(p, odds) / combo(legs)期望值 / 串关联乘

独立强度模型（比率法 + 收缩）

hg  = 主队主场场均进球     hga = 主队主场场均失球
ag  = 客队客场场均进球     aga = 客队客场场均失球

lgHome = (hg + aga) / 2        // 联赛基准，两估计互相印证
lgAway = (ag + hga) / 2

shrink(x, p) = 1 + (x − 1) · p / (p + K)      // K = 8
attH = shrink(hg / lgHome, 主队主场场次)
defH = shrink(hga / lgAway, 主队主场场次)
attA = shrink(ag / lgAway, 客队客场场次)
defA = shrink(aga / lgHome, 客队客场场次)

λ主 = lgHome · attH · defA
λ客 = lgAway · attA · defH

为什么必须主客分离：主场和客场是两支不同的球队。用总数据拟合会把「主场强、客场弱」的球队抹平。

九、交付前自检

  • 回测层已完成，且每个命中率都配了「盘口隐含」对照
  • 场次数 = 综合预测行数 = 购买方案行数
  • 每场都有 比分分布 / 总进球 / 胜平负 三段，无「待定」
  • 没有任何一处出现单一比分预测
  • λ 注明了市场值、独立值、伤停修正与融合权重 k
  • 表格数字与 predictMatch 输出逐字一致
  • 串关全部标注 EV，结论为单关优先
  • 数据卫生八条逐项有状态，缺项写明原因
  • 尾页含源清单、访问时间（分钟级）、缺失字段、风险披露
  • PDF 已落到工作区，链接可用
