# 数据源与采集

核心四层（默认必抓）+ 扩展源（按缺口启用），按可信度排序。**每一份报告尾页必须列出实际用到的源、访问时间（到分钟）、以及哪些字段缺失。**

## 二、各源取什么、怎么取

### A 竞彩官网 https://www.lottery.gov.cn/jc/jsq/zqspf/
- 页面按日期分组：周六 / 周日 / 周一，编号形如 `六023`、`日013`、`一006`，**原样保留**，它是报告索引。
- 玩法子页：胜平负、让球胜平负、总进球、比分、半全场。逐个玩法抓，不要只抓胜平负。
- 支持率三项对应 主/平/客，与赔率三项同序；某场只开让球盘时，支持率对应让球盘三项。
- 未开售的玩法字段为 `null`，**不要用 0 填充**，否则去水算错。
- 截止销售时间要一并记录（它决定这份报告的时效边界）。

### B 捷报 https://cp.nowscore.com/
- 从竞彩列表页进入每场的详情，再进 亚盘 / 欧赔 / 大小球 / 数据分析 子页；子页链接以实际抓到的为准，**不要手写猜测 URL**。
- 取初盘价（开盘价）与现价两组，分开存。初盘缺失就算「无价格移动」，**不要用现价冒充初盘**。
- 亚盘记录：让球数 + 主客水位（水位变化比让球数变化更早反映聪明钱）。
- 大小球记录：盘口线（2/2.5/3）与大小水位。
- 球队数据页取：近 10 场、主客分列、进球/失球、角球、黄牌。

#### B 层三个关键子页（v2 模型的输入来源）

在 `cp.nowscore.com` 的竞彩列表页，每场行内可拿到捷报赛事 ID（形如 `2993853`），随后：

| 子页 | 地址 | 取什么 |
|---|---|---|
| 分析页 | `https://live.nowscore.com/analysis/{id}cn.html` | **联赛积分（总/主/客/近6 分开的 赛-胜-平-负-得-失-净-得分-排名-胜率）**、**联赛盘路走势（让球赢/走/输 + 让胜率 + 大小球率，总/主/客/近6 分开）**、对战往绩、天气与场地 |
| 指数页 | `https://live.nowscore.com/odds/match/{id}.htm` | 每家公司 6 组数据：让球初指、让球即时、标准初指、标准即时、进球数初指、进球数即时 |
| 盘路页 | `https://live.nowscore.com/panlu/{id}.html` | 历史盘路明细 |
| 裁判页 | `https://live.nowscore.com/info/referee/{id}.htm` | **纪律层（v5.1）唯一结构化来源**，字段见下 |

#### B 层裁判页字段（v5.1 纪律层输入）

页面固定四段，全部按「场均」口径给出，主客/近况分开：

| 段 | 字段 | 说明 |
|---|---|---|
| 主裁判执法统计 | 场次、胜平负、**场均犯规、场均黄牌、场均红牌**、胜率 | 分「所有赛事」与「该联赛」两个口径；主队视角与客队视角各一行。样本量通常 200–300 场 |
| 对阵往绩 | 这两队在该裁判哨下的牌数 | 样本常为 1，仅作披露 |
| 近场（赛事口径） | 该裁判近期在联赛的场均牌 | 与所有赛事口径对照，看趋势 |
| 球队纪律 | **球队近 10 场 / 近 5 场（本侧：主队取主场、客队取客场）的场均犯规、场均黄牌、场均红牌**，含对手口径 | 红牌风险因子的球队侧输入 |

解析要点：
1. 无裁判数据时页面显示「本场比赛暂无裁判分析数据」——低级别杯赛常见，此时纪律层不启用，数据卫生层标「未公布」。
2. 球队段的「本侧」口径要对齐：主队取「主场」行，客队取「客场」行，与主客分离得失球同一原则。
3. 黄牌/犯规只做「高摩擦场次」披露（近 5 场牌数比近 10 场上升 ≥30% 且裁判场均黄牌 ≥2.3），**不直接进 λ**。

与裁判页互补的停赛信息：**累积黄牌停赛名单**（官方公告/直播吧）走既有 injuryAdj 通道——核心球员停赛等价于伤停，按「可查源、量化到 λ」的铁律处理，红牌风险因子只管「比赛中被罚下」这一件事。

**指数页表格固定列序（24 个 TD）：**

```
公司 | 让球初指(主/盘/客) | 让球即时(主/盘/客) | 标准初指(主/和/客) | 标准即时(主/和/客) | 进球数初指(大/盘/小) | 进球数即时(大/盘/小) | 链接(详 统 主 客 同)
```

注意两点：

1. HTML 用**大写** `<TR>` `<TD>`，正则必须加 `re.I`，否则一行都匹配不到。
2. 部分公司（如立博）不开亚盘，只有 12 个数据列。**不要删除空单元格来判断列位**——删空会把后续列整体错位，得出「主胜 1.06」这种荒谬值。按 `len(cells) >= 19` 取 18 个数据列、否则取 12 个，再按固定偏移解析。
3. 解析后用合理性校验筛掉错位行：三项欧赔均 ≥1.01 且倒数和落在 1.00–1.30。不通过就不计入均值。

**盘口线转数值**：平手 0、平/半 0.25、半球 0.5、半/一 0.75、一球 1、一球/球半 1.25、球半 1.5、球半/两 1.75、两球 2、两球/两球半 2.25、两球半 2.5；`受*` 取负。大小球线同理，`2.5/3` 取 2.75。

**这一层直接决定独立模型能否建立。** 主客分离得失球缺失时，报告必须降级为「纯盘口分析」并在数据卫生层写明。

### C 直播吧 https://www.zhibo8.com/
- 首页新闻流与足球频道：`https://news.zhibo8.com/zuqiu/`（实际抓到的栏目链接为准）。
- 取赛前 3 天到开赛前的新闻：伤停、首发、停赛、主帅表态、赛程冲突、更衣室风向。
- 中文快讯常先于官方公告，**但只能作为线索**：任何影响模型的伤停，必须有第二条来源（官方号/跟队记者/另一家媒体）才算确认，未确认只写进「待验证」。

### D 联网搜索（关键词模板）
中文：
- `<球队> 伤停 名单 <日期>` / `<球队> 首发 预测` / `<球员> 伤 缺阵`
- `<联赛> 保级 争冠 形势 <赛季>` / `<球队> 轮换 欧战`
- `<城市> 天气 <开赛日>` / `<主裁> 执法 数据`

英文（补中文源缺失的 xG 与球员级数据）：
- `<team> injuries team news <date>`、`<team> expected lineup`
- `<team> xG xGA stats <season>`、`<player> shots per 90`
- `<league> dead rubber motivation`

**搜索纪律**：每条进入模型的数字必须能点回原页面；同一字段多家冲突时，取官方/最新，并在报告里写「A 源取 X，B 源取 Y，采用 X」。

### E 扩展源采集要点

**球探 zq.titan007.com（盘路）**
- 用来补「盘路」这一层：某队近 10 场让球盘的赢盘/输盘率、大小球盘路走势。这是竞彩让球判断的常见盲区。
- 标准盘与亚洲盘对照页可识别同一场比赛在两种盘口体系下的定价差异，差异大时说明市场对赛果方向有分歧。

**捷报资料库 info.nowscore.com**
- 前瞻页通常已整理好近况、伤停摘要、历史交锋，可作为起点，但**每个数字仍要回到 CP 页或原始数据页核对**，前瞻文本里的表述常是旧数据。

**500 彩票网 500.com**
- 用作竞彩赔率的第二校验源。与竞彩官网不一致时，以官网为准，差异记入数据卫生清单。

**OddsPortal / Oddspedia（跨庄与变价方向）**
- 关键不是「有多少家」，而是**变价方向**：同一联赛多家庄同步朝一个方向移动，说明有真实资金或新信息。
- 两者都有反爬与付费接口，优先用 Oddspedia 的公开 widget 或只抓单场页；抓不到就写「跨庄数据缺失」，不要编。
- 收盘价（closing line）比开盘价更接近真实概率，复盘时用收盘价评估自己的模型。

**Betfair / Smarkets（真实成交）**
- 看的是成交额与最优价的宽度：某方向挂单薄、价差宽，说明市场没有共识，此时不要重仓该方向。
- 免费 key 只返回延迟快照，对赛前分析足够；不要为了实时去付费，赛前不需要毫秒级。

**Pinnacle / 亚洲锐利庄（市场共识价）**
- margin 常在 2%–4%，去水后的概率最接近真实概率。**做 value 判断时，用锐利庄去水价当基准，而不是竞彩价**，否则会把竞彩的高 margin 误读成「有价值」。

**FBref / Understat（xG）**
- FBref 的 xG 来自 StatsBomb，覆盖面广；Understat 只覆盖五大联赛 + 俄超，但队级 xG 与 xGA 更干净。
- 取数时固定一家、固定赛季区间（建议近 10 场或当前赛季），**不要两家混用**，否则 xG 口径不一致。

**Sofascore / FotMob（首发与赛中）**
- 赛前 60–75 分钟的首发是最高价值信息。抓到首发就立刻重算 λ 并标注「基于首发修正」。

**Transfermarkt（伤停与身价）**
- 伤停页按联赛列出，但更新比官宣慢，只作「谁在伤」的清单，具体能否出场以赛前发布会/官方号为准。
- 身价用于替补深度与阵容质量的量化（替补席总身价 vs 对手）。

### F 多源交叉校验

每份报告至少做三组校验，并把结果写进数据卫生一节：

1. **赔率三源对齐**：竞彩官网 vs 捷报现价 vs 500/球探。同一场同一时点的主胜赔率差异 > 0.05 时，说明快照时点不同，需重新抓。
2. **伤停双源确认**：直播吧/媒体传闻 vs 官方公告或两家以上媒体。单源只进「待验证」。
3. **xG 单一口径**：一份报告里 xG 只用一个供应商（FBref 或 Understat），不混。

校验不通过时，处理方式固定为：降级该结论 → 在报告中写明 → 不删除原始数据。

## 三、数据结构

每行一个数组，顺序固定：

```
[no, lg, home, away, time, hc, spf, rq, supSPF, supRQ, zjq, open]
```

- `spf` / `rq`：三项赔率数组，未开售为 `null`
- `supSPF` / `supRQ`：三项支持率数组（整数百分比，原值使用，不归一化）
- `zjq`：8 档总进球赔率（顺序 0、1、2、3、4、5、6、7+），无则 `null`
- `open`：初盘欧赔三项，无则 `null`
- `hc` 以主队视角：`-1` 主让一球，`+1` 主受让一球；深度让球可为 `-2`、`-3`

## 四、采集顺序与时效

1. 先抓竞彩官网全部在售场次与全部玩法（这份是定价基准，最后抓会与其他源错时点）。
2. 再抓捷报初盘与现价，记录抓取时间；补球探的盘路与标准盘/亚盘对照。
3. 再刷直播吧、捷报资料库与搜索，补齐伤停、首发、动机、天气、裁判；xG 固定一家取。
4. 若需要跨庄对齐或查聪明钱，再抓 Oddspedia / OddsPortal / Betfair 快照，用于判断变价方向而非直接进模型。
5. 若距开赛不足 90 分钟，**重新抓一次竞彩赔率与首发**，只更新变化项，并在报告封面标注「快照时间」与「最后更新」。

## 五、常见坑

1. 支持率三项可能不等于 100（四舍五入），不归一化，直接用原值算 Δ。
2. 一场同时开胜平负和让球时，两个盘 margin 独立计算，不混。
3. 已完场只进复盘，不进判定，不与未开赛混排。
4. 跨日场次（周日场周一凌晨开赛）按竞彩编号归类，不按自然日归类。
5. 不同供应商的事件定义不同（射门、Big Chances、xA），一份报告内不混用两家口径。
6. 重伤/停赛只在「官方确认」后才允许改 λ；传闻只写进文字。
7. 抓不到的字段写「缺失」，不要用模型默认值悄悄补上。
